# Кеш справочников: Rust (scc::HashIndex) vs .NET (ConcurrentDictionary)

## Задача

Сервису нужны справочники (пиццерии, продукты). Они лежат в Kafka. При старте
сервис читает топик с начала до конца (прогрев) и держит всё в памяти. Пока прогрев
не закончился, сервис отвечает 503. Потом он отдаёт значения по ключу и на лету
применяет новые сообщения: последнее значение побеждает, а tombstone удаляет ключ.

Я хочу сравнить Rust и .NET на одной задаче:
- время прогрева;
- память (RSS);
- сколько get в секунду выдерживает кеш при нескольких потоках-читателях и одном писателе;
- задержки p50 / p95 / p99 / p99.9 / max;
- паузы сборщика мусора у .NET.

Почему `scc::HashIndex`: чтение идёт без блокировок (`peek_with`), поэтому
читатели не ждут писателя. Старое значение освобождается позже, когда его уже
никто не читает.

## Что где лежит

```
rust/src/main.rs     кеш на scc::HashIndex: демо, тесты, замеры
dotnet/Program.cs    то же самое на ConcurrentDictionary
analyze/analyze.py   запускает оба замера по очереди и строит графики
```

Kafka здесь не используется. Сообщения я генерирую сама прямо в программах,
чтобы сравнивать только сам кеш.

## Как запустить

```bash
# Rust
cd rust
cargo run --release          # демо: прогрев, 503 → 200, замена, удаление
cargo test --release         # 5 тестов

# .NET
cd dotnet
dotnet run -c Release        # то же демо
dotnet run -c Release -- test

# Замеры и графики (нужен matplotlib: pip install matplotlib)
python3 analyze/analyze.py --run                  # 3 запуска, 1 млн записей
python3 analyze/analyze.py --run --runs 5         # побольше запусков
```

## Как устроен замер

1. Прогреваю кеш на N записей и замеряю время и память.
2. Ещё 1 секунду гоняю get без записи результатов, чтобы прогрелся JIT у .NET.
3. Дальше идут ступени: 1 писатель (~1000 обновлений/с) и 1, 2, 4… читателей,
   вплоть до числа ядер. Все потоки стартуют одновременно через `Barrier`.
4. Каждый get копирует значение, в обоих языках одинаково.
5. Задержку я записываю у каждого 16-го get, а max считаю по всем get.
6. Rust и .NET запускаются по очереди, несколько раз. На графиках показано среднее.
